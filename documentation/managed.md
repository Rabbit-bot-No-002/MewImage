# 托管账号与服务商模板

> 由管理员在服务端托管上游连接信息，让使用者只看到模型和参数，看不到地址与 Key。

托管账号是管理员创建的一类特殊账号：连接上游服务商所需的地址、API Key 和接口模板全部放在服务器上，使用者只需要选模型和填参数。它适合把生图能力发给不方便自行配置上游的人。

## 解决什么问题

普通账号的服务商配置保存在使用者自己的浏览器里，每个人都要自己准备地址和 Key。托管账号把这一步收归管理员：管理员在后台维护连接信息，账号侧看不到也不需要填写，因此不会因为截图、导出或误操作把凭据带到别处。

## 权限与隔离边界

托管账号创建后即为已审批普通用户，拥有生成、手动同步、服务器资源存储、模板广场和收藏能力，权限与已审批普通用户相同。区别在两点：

| 维度 | 已审批普通用户 | 托管账号 |
| --- | --- | --- |
| 上游连接信息来源 | 自己在浏览器里填写 | 管理员在服务端维护 |
| 生成入口 | 普通代理入口 | 强制走独立托管 Proxy 入口 |
| 可提交内容 | 地址、Key、模型与参数 | 配置 ID、允许的模型、生成参数和图片 |

> 🛑 **连接信息不会下发给使用者**
>
> 托管用户的浏览器、IndexedDB、同步快照、工作区 ZIP、任务详情和错误信息中都不会出现上游地址、API Key、密文或 Key 提示。管理员接口同样不回显完整 Key，只会保留一个末尾提示（形如 `••••3456`）。

后端按登录账号校验配置归属、启用状态和模型白名单。普通代理入口会拒绝托管账号，普通账号也不能调用托管入口，两侧互不通用。

## 服务端加密

托管连接信息使用 `MEW_MANAGED_PROVIDER_SECRET` 做认证加密，加密时带随机 Nonce 和 AAD，密文与账号、配置绑定。每个托管账号可以拥有多个协议、多个模型的配置。

> ⚠️ **先把密钥固定并备份**
>
> `MEW_MANAGED_PROVIDER_SECRET` 一旦丢失，已有的托管配置无法恢复。用 `openssl rand -hex 32` 生成固定的 64 位十六进制随机值，并随数据库一起安全备份。

密钥缺失时的行为取决于是否已有托管数据：没有托管数据时缺失密钥不影响启动；已经存在托管数据但密钥缺失或无法解密时，后端会拒绝启动并给出恢复说明。

## 管理员维护动作

- 单项新增、编辑、删除和启停托管配置。
- API Key 只写入不回显，页面只显示末尾提示。
- 批量更新凭据只允许选中相同服务商协议与接口模式的配置：先完整校验全部目标，再在单个事务里更新，任一失败全部回滚。
- 批量更新时留空 Key 表示保留原值；只填地址或只换 Key 都可以，保存后仍然只显示末尾提示。

## 服务商模板

模板用来把一套配置复制给多个托管账号，避免逐个手填：

1. 建立加密的服务商模板。
2. 把模板分配给多个托管账号，分配时为每个账号生成独立配置副本，并记录来源模板修订号。
3. 之后模板的修改不会自动影响已分配的账号。

需要让账号跟进模板变更时，管理员先预览差异，再手动同步到全部或部分关联账号。同步会保留各账号的启停状态，以及仍然有效的当前模型。删除模板只解除来源关联，不会删除已派生的账号配置。

## 临时密码

托管账号创建时会生成一个只显示一次的临时密码，并强制首次登录修改密码。

管理员也可以为包括普通账号和其他管理员在内的任意账号重置临时密码：重置会清除锁定状态、递增 Session 版本，使该账号的旧会话立即失效，并要求下次登录时改密。重置结果同样只在一次操作中显示，请当场转交。
