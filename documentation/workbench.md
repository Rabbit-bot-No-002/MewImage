# 工作台与生图

> 三类服务商、请求策略、生成参数、生图队列与透明背景的实际用法。

工作台是生图主界面：选好服务商配置、写好提示词、调好参数后提交，结果落到左侧画廊。

## 三类服务商

配置按协议分成三类，协议之间不混用，也不同协议共享配置；改 Base URL 不会切换你已经选好的服务商类型。

| 类型 | 协议与默认 | 适用场景 |
| --- | --- | --- |
| `OpenAI Image` | 默认模型 `gpt-image-2`，支持 `Images API` 与 `Responses API`；Responses 主模型默认兼容 `gpt-5.5`，通过 `image_generation` 工具生成 | 需要官方质量档位、审核参数、Codex 兼容开关与透明背景 |
| `Nano Banana` | Google `generateContent`，默认模型 `gemini-2.5-flash-image`；官方地址用 `x-goog-api-key`，兼容中转地址可用 Bearer | Google 系图像模型或对应中转站 |
| `OpenAI 兼容` | 面向第三方中转站与 Nano Banana 的 OpenAI 兼容协议；文本生图与参考图编辑使用独立请求构造 | 只提供 OpenAI 形状接口的中转站 |

`Nano Banana` 按实际尺寸映射 `aspectRatio`，Gemini 3 图像模型额外映射 `imageSize` 的 `1K/2K/4K`；`OpenAI 兼容` 的参考图编辑使用 multipart 并按选择顺序上传。`CustomHttp` 是保留的高级兼容能力，支持模板字段映射与自定义响应路径。

## 请求策略

访问模式决定请求从哪里出去：

| 模式 | 行为 |
| --- | --- |
| `Direct` | 浏览器直接请求上游，受浏览器 CORS 限制 |
| `Proxy` | 统一向 `/api/providers/generate` 提交后台任务，并轮询任务状态 |
| `Smart` | 按服务商、接口模式和请求类型预先选择直连或代理；请求发出后不自动切换链路重试 |

`OpenAI Image` 另有接口模式：`Images API` 负责文本生成与 multipart 参考图编辑，编辑走 `/v1/images/edits`；`Responses API` 用独立主模型和 `image_generation` 工具，支持普通 JSON 与 SSE 流式解析，连续修改可用 `previous_response_id`。带参考图的 OpenAI/兼容编辑请求优先走 multipart 代理，`Responses API` 的 Smart 优先代理，`Nano Banana` 的 Smart 可优先直连、失败后由你手动重试。代理提交后立即返回任务 ID，前端用 `status_only=true` 轻量短轮询，取得处理预算后才领取完整结果。

## 生成参数

| 参数 | 可选值 | 说明 |
| --- | --- | --- |
| 数量 | `1–4` | 单次生成张数 |
| 质量 | `auto` `low` `medium` `high` `xhigh` `max` | 已知旧模型不允许选择 `xhigh`/`max`，未知中转别名仍可显式尝试 |
| 格式 | PNG、JPEG、WebP | `OpenAI Image` 可配置 |
| 压缩率 | `0–100` | `OpenAI Image` 可配置 |
| 审核策略 | 按服务商提供 | `OpenAI Image` 可配置 |
| 透明背景 | 关闭 / API 原生 / 本地去背 | 两种透明模式都禁用 JPEG |
| Codex 兼容 | 开 / 关 | 对请求参数做兼容处理 |
| 模型 | 当前配置的模型列表 | 见下文「多模型配置」 |

任务可以在进行中停止，停止前二次确认；客户端停止只中止本地等待，已到达上游的请求仍可能产生消耗。

## 分辨率

| 模式 | 行为 |
| --- | --- |
| 自动 | 优先沿用连续修改底图或参考图尺寸；没有参考图时回落到 `1024 × 1024` |
| 模型自动 | 真正发送 `size=auto`，按 `3840 × 2160` 预留预算，实际尺寸从结果图片读取；目前仅 `OpenAI Image` 可用 |
| 按比例 | `1K`、`2K`、`4K` 三档，预设 `1:1`、`3:2`、`2:3`、`16:9`、`9:16`，也可输入 `5:4`、`2.39:1` 等自定义比例 |

| 等级 | 1:1 | 3:2 | 2:3 | 16:9 | 9:16 |
| --- | --- | --- | --- | --- | --- |
| 1K | 1024×1024 | 1152×768 | 768×1152 | 1280×720 | 720×1280 |
| 2K | 2048×2048 | 2016×1344 | 1344×2016 | 2048×1152 | 1152×2048 |
| 4K | 2880×2880 | 3504×2336 | 2336×3504 | 3840×2160 | 2160×3840 |

显式尺寸要求宽高至少 `256`、为 16 的倍数、单边不超过 `3840`、宽高比不超过 `3:1`、总像素在 `655,360–8,294,400`。超出 `1:3～3:1` 的输入会规整到最近的合法边界，面板实时显示实际生效尺寸，例如 4K `2:1` 得到 `3840 × 1920`。上游仍可能降级，结果以实际解码尺寸为准。

> ⚠️ **模型自动只对 OpenAI Image 生效**
>
> 其他协议只能手动选择输出尺寸。

## 多图生成

上游原生支持多图时可复用一次请求结果；`Nano Banana` 和 `Responses API` 等单图链路由前端按数量拆分请求并合并。任务统计以真正写入本地的图片为准：空结果或写盘失败都标记失败，不产生幽灵任务。

## 生图队列

提示词下方的「队列：关 / 开」开关默认关闭，只保存在当前设备的 LocalStorage，不进入工作区、ZIP 备份、会话项目包或云同步。开启后每次提交立刻建立 `Running` 任务和画廊等待卡，编辑器不被锁定，你可以继续改提示词、参考图、配置、尺寸、质量和透明模式再提交；每个任务在提交时独立快照输入与参数。队列与连续修改互斥：开启队列会退出连续修改，从结果卡进入连续修改会关闭队列；已提交的后台任务继续执行，但完成后不会自动改变连续修改底图。

| 限制 | 值 |
| --- | --- |
| 活动任务上限 | 20，第 21 个返回容量已满错误 |
| 任务总等待上限 | 30 分钟 |
| 浏览器软预算 | `deviceMemory × 64 MiB`，限制在 `192–512 MiB`；读不到时使用 `256 MiB` |

| 阶段 | 估算方式 |
| --- | --- |
| 参考图准备 | `16 MiB + 参考图总字节 + 最大单张字节` |
| 结果处理 | `32 MiB + 响应字节两倍 + 最大单图像素八倍`；本地去背再加最大单图像素八倍 |

实际并发还受参考图字节数、分辨率和数量影响。代理任务提交成功后立刻释放参考图准备预算，等待上游只占活动槽；结果完成时按「结果优先、同级 FIFO」领取处理预算。单阶段超过软预算且无其他占用时允许独占执行，`Direct` 与旧后端兼容链路则在请求全程持有完整预算。

结果逐张处理并暂存到 IndexedDB，全部完成后才发布正式任务，刷新页面可恢复暂存结果。等待卡可单独停止，设置栏的「停止全部」二次确认；取消后任务卡直接移除，迟到响应不会回写。

## 透明背景

| 模式 | 行为 |
| --- | --- |
| 关闭 | 发送普通背景参数 |
| API 原生 | 向 `OpenAI Image` 发送 `background=transparent` |
| 本地去背 | 上游仍用普通背景参数，由浏览器做色键去背 |

本地去背会向实际请求追加纯色背景约束：主体含绿色系时用纯洋红 `#FF00FF`，否则用纯绿 `#00FF00`；浏览器收到图片后用色键算法生成带 Alpha 的 PNG 或 WebP。无法识别键色、主体被完全清除或编码失败时保留原图，并在任务详情记录原因，任务与界面仍保存你的原始提示词。两种透明模式都只允许 PNG 或 WebP，选 JPEG 会自动切换为 PNG。

## 多模型配置

一条站点/协议配置可以保存有序的多个图片模型 ID，`model` 字段记录当前实际使用的那个；地址、API Key、协议、访问模式和输出选项由这些模型共享。设置页可添加任意中转模型 ID、选择当前模型、删除非最后一个模型，至少保留一个，草稿在点击「保存」后统一应用。工作台快捷菜单按配置和协议分组，组内一步切换并标识当前项；模型变化会更新配置修订并持久化，但不改变已提交任务的快照。`Responses` 主模型保持独立单值，不混入图片模型列表。多模型列表参与完整备份与手动云同步。
