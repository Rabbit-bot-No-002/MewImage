# 已知边界与路线图

> 当前明确不做的事、发布前的验收要求，以及按优先级排列的优化方向。

这一页说明当前版本不承诺什么、发布前要验证什么，以及后面准备往哪走。下面列出的优化方向都属于未来计划，不代表已经实现。

## 当前明确边界

| 边界 | 说明 |
| --- | --- |
| 第三方中转站能力 | 提供 Images API 与 Responses API 遮罩编辑，但不保证未明确声明兼容的中转站支持 Responses 图片工具；真实上游能力以对方的协议和账号权限为准 |
| 纯静态部署 | 不提供完整纯静态部署，静态页面无法替代后端代理、账号、同步和资源服务 |
| 桌面客户端 | 暂未提供桌面客户端、Windows 安装包、AppImage 或 Arch 包 |
| 自动同步 | 不自动执行云同步，必须由用户手动触发 |
| 存储迁移 | 不提供 Local 与 S3 之间的自动迁移工具 |
| 账号体系 | 不提供邮箱验证、找回密码或多因素认证 |
| 协作 | 不提供多人共享同一工作区或实时协作 |
| CustomHttp | 不是默认主流程能力 |
| 请求参数 | 不保证所有第三方中转站完整支持请求的画幅、质量、数量和分辨率，详情页展示实际结果 |

## 已知运行上限

这些是设计上已经落地的限制，用来把内存和可用性控制在可预期范围内。

| 维度 | 当前上限 |
| --- | --- |
| 活动生成任务 | 最多 20 个，第 21 个返回容量已满错误；实际执行并发由 192–512 MiB 的自适应字节预算决定 |
| 浏览器内存预算 | 按 `deviceMemory × 64 MiB` 计算并限制在 192–512 MiB，浏览器不报告时用 256 MiB；单阶段估算超预算时可独占运行 |
| 参考图 | `multipart` 总量 192 MiB，最多 10 张普通参考图，单张最大 32 MiB，遮罩独立计数 |
| 请求体 | 普通 JSON 2 MiB、同步 JSON 32 MiB、单资源上传 64 MiB、上游生成响应 256 MiB |
| 单图与用户配额 | 单文件默认 64 MiB，每个已审批用户默认 5 GiB，超额后仍可读取和删除 |
| 本地原图缓存 | LRU，默认最多 6 张、约 48 MiB |
| 超时 | 上游连接 10 秒，图片下载 120 秒，生成任务 30 分钟，生成结果 TTL 10 分钟 |
| 容器内存 | Compose 默认 1 GiB 作为最终保险，不是常规内存目标 |

## 验收要求

### 构建与测试

自动化检查覆盖以下命令，CI 与本地发布前都应通过：

```bash
cargo fmt --all -- --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo check -p mew-image-frontend --target wasm32-unknown-unknown
cd frontend && trunk build --release --locked --dist dist-app
cargo deny check advisories
git diff --check
```

这套检查覆盖 Rust workspace、前端单元测试、WASM 目标、严格 Clippy、Trunk Release 构建、格式与差异检查。

> ℹ️ **需要部署者按环境自行执行的验证**
>
> 真实上游计费测试、三主题浏览器手测和容器压力测试不在自动化范围内，需要你在自己的环境里跑一遍。这三项都依赖真实凭据、真实浏览器或真实负载，无法在通用 CI 里替代。

### 核心回归场景

以下行为在升级前后都应人工确认：

| 场景 | 期望 |
| --- | --- |
| 游客生成 | 能生成图片，且服务器不保存其工作区和图片 |
| 生成模式 | 文生图、参考图编辑、连续修改和多图数量均正常 |
| 协议隔离 | OpenAI Images、OpenAI Responses、Nano Banana、OpenAI 兼容互不干扰 |
| 透明背景 | API 原生与本地去背都输出真实 Alpha；本地模式部分失败时回退原图，成功结果不额外保存纯色原图 |
| 参考图 | 顺序、`SHA-256` 去重和重复导入正常 |
| 连续修改 | 清除连续修改后，新请求不携带历史图片 |
| 会话 | 重命名立即显示，删除会话不影响全局收藏 |
| 分页与预览 | 画廊和收藏夹分页正常，详情页与全屏预览正常 |
| 危险操作 | 删除操作均使用统一二次确认 |
| 账号管理 | 登录、审批、禁用、恢复、删除用户和改密正常 |
| 同步触发 | 登录后不自动同步，点击同步才发起网络请求 |
| 删除墓碑 | 删除记录同步到其他设备后不会复活 |
| 缺图同步 | 同步带参考图、收藏图和导入图时，不因当前设备缺少原图而整体中止 |
| 存储隔离 | Local 和 S3 对象按用户隔离 |
| 安全拒绝 | 非法上游地址、越权资源和过期上传 token 被拒绝 |

## 后续优化方向

### P0：可靠性与可运维性

| 方向 | 要解决的问题 |
| --- | --- |
| 正式 migration 文件与版本管理 | 替代集中在启动代码里的建表与兼容逻辑 |
| 同步进度可视化 | 阶段进度、每张图片上传进度、失败资产列表和可重试入口 |
| 墓碑压缩或安全回收 | 避免长期运行后墓碑无限增长 |
| Local 与 S3 双读迁移期 | 配合自动迁移 CLI 或管理页面 |
| 配额与限流管理界面 | 监控指标和按用户覆盖配置，当前只有默认单图/总容量/游客频率限制 |
| 结构化审计日志 | 同时严格排除 API Key、提示词、图片和 Base64 |
| 统一 CSRF token | 为所有登录写接口补充防护 |

### P1：性能

| 方向 | 要解决的问题 |
| --- | --- |
| 迁移重计算到 Web Worker | ZIP 导入导出、图片哈希、缩略图和 WebP 转换不再阻塞主线程 |
| 继续拆分大组件 | 当前设置和工作区组件仍接近 500～1000 行 |
| 超大任务列表虚拟滚动 | 或改用更细粒度查询 |
| `IndexedDB` 批量事务 | 把多 ID 逐项读取合并为批量接口 |
| Responses 图片流增量解码 | 降低大型 Base64 JSON 峰值，改前必须保留现有兼容解析作为回退 |
| 并发上限细化 | 从全局任务上限细化为按用户、按访客来源的并发与排队限制 |
| 降低流式校验峰值内存 | 当前已在读取阶段做有界大小与魔数校验 |

### P1：同步体验

| 方向 | 要解决的问题 |
| --- | --- |
| 显式方向选项 | 支持「只上传」「只下载」「双向合并」 |
| 首次同步预估 | 新设备同步前给出图片数量、数据量和耗时 |
| 断点上传与可配置并发 | 同时控制浏览器与服务器内存 |
| 同步前差异预览 | 展示新增、更新和删除数量 |
| 缺失原图工具 | 对永久缺失原图的资产提供定位、移除和重新绑定 |

### P2：桌面客户端

用 Tauri 2 复用 Leptos CSR UI，把服务商网络层抽成独立 Rust crate 供 Axum 与 Tauri 共用，桌面端通过 `reqwest` 直连上游以避免浏览器 CORS。计划提供便携模式（SQLite 与图片放在程序旁的 `data/`）和标准安装模式（系统应用数据目录），优先支持 Windows、Linux AppImage 和 Arch `PKGBUILD`，macOS 在具备测试设备后再考虑。

### P2：账号与管理

用户自助删除账号及服务器数据、管理员配额设置与代理权限开关、存储占用排行；按部署需求增加邀请注册码或关闭公开注册；需要公网大规模开放时再增加验证码、邮箱验证、密码重置和可选 MFA；以及管理员操作审计与敏感操作二次验证。

### P2：服务商扩展

把服务商协议适配从大型 `match` 分支拆成独立适配器模块，为每个适配器建立请求与响应 fixture 测试，增加服务商能力声明（参考图、多图、画幅、2K/4K、格式、质量），按能力动态隐藏无效参数以减少「界面可选但上游忽略」的误解，并为 `CustomHttp` 提供安全的模板预览、测试请求和字段校验工具。

### P3：产品体验

会话、提示词和收藏夹搜索；收藏标签、备注和排序；失败任务一键修正参数后重试；批量下载（需要控制浏览器内存，避免一次读取全部原图）；可选的 WebDAV 或用户自有 S3 同步后端；面向高级用户的快捷键设置与可导入导出的界面偏好。

## 文档维护要求

- 新增或移除用户可见功能时，同步更新项目要求文档和 `README.md`。
- 新增环境变量时，同步更新 `.env.example`、Docker Compose 和 `README.md`。
- 修改同步 schema 时记录版本、兼容策略和迁移测试。
- 修改对象键规则时提供 Local/S3 数据迁移说明。
- 修改服务商请求协议时增加请求体和响应解析测试。
- 安全边界变化必须在部署文档中明确默认值与风险。
