# 账号、审批与登录防护

> 谁是游客、谁已审批通过，以及注册、审批、限流与会话的完整规则。

喵图把「用得上」和「存得上」拆成了两件事：不登录就能完整使用本地工作台，登录并审批通过后才获得云端同步与服务器图片存储。注册之后默认处于待审批状态，需要管理员处理。

## 四种模式的权限边界

| 能力 | 游客 | 已注册待审批 | 已审批用户 | 管理员 |
| --- | --- | --- | --- | --- |
| 本地生成工作台 | 可用 | 可用 | 可用 | 可用 |
| 后端代理 | 由部署配置决定，默认可用 | 按普通代理规则 | 可用 | 可用 |
| 云端同步 | 不可用 | 不可用 | 手动同步 | 手动同步 |
| 服务器图片存储 | 不写入 | 不写入 | 可用 | 可用 |
| 管理功能 | 不可用 | 不可用 | 不可用 | 审批、禁用、恢复、删除 |

`CustomHttp` 协议只对已审批登录用户开放；待审批和已禁用账号按游客规则处理。

> ⚠️ **未登录不会把任何工作数据写进服务器**
>
> 用户未登录时，历史、图片、会话、收藏和服务商配置都不会写入服务器数据库与对象存储。游客走代理时 API Key 只在请求期间进入后端内存，不落数据库、对象存储，也不进业务日志。浏览器 IndexedDB 始终是本地工作台的主数据源。

游客模式在界面上会明确标注为「游客本地 + 代理模式」，便于你随时确认当前处于哪种状态。

## 注册与登录

登录不是使用前提。注册入口只负责建立账号，注册成功后状态默认为 `pending`（待审批）。

- 用户名至少 3 个字符，由数据库唯一索引保证不重名；注册页提供用户名可用性检查。
- 密码至少 10 位，同时包含大写字母、小写字母、数字和符号；注册与修改密码都要二次输入确认。
- 密码使用 Argon2 哈希存储，服务器不保存明文。
- 登录会话保存在 SQLite，后端重启后仍然有效。
- 密码错误提示显示在对应输入框附近，不会混进主生成状态区域。

待审批用户能登录、查看自己的审批状态、修改密码，但同步与服务器图片存储此时不可用。

## 第一个管理员

首位管理员通过部署变量初始化，而不是预设账号：

| 变量 | 作用 |
| --- | --- |
| `MEW_ADMIN_TOKEN` | 管理员初始化口令，建议用密码管理器生成 |
| `MEW_ALLOW_ADMIN_SETUP` | 是否允许通过初始化口令创建第一个管理员，默认 `true` |

系统里还没有管理员时，注册界面可以展开「管理员初始化」入口，填入口令即可创建第一个管理员。正确口令只能创建一次；系统已有管理员后，入口永久隐藏，后端也会拒绝再次初始化。升级前已存在的账号，在系统尚无管理员时可以登录后用同一口令把自己升级为首位管理员。

> 💡 **初始化完成后建议关掉入口**
>
> 第一位管理员建好后，把 `MEW_ALLOW_ADMIN_SETUP` 设为 `false` 可以彻底关闭这条路径。改完 `.env` 记得重建容器才生效。

## 审批与账号状态

管理员可以批准、禁用、恢复和永久删除普通用户。管理员不能禁用或删除当前登录的自己，批量操作也不能包含管理员账号。删除用户时，会一并删除该用户的同步快照、服务商模板、图片索引、上传凭证以及 Local/S3 对象命名空间。

审批状态变化会递增会话版本，因此角色或审批状态改变后旧会话立即失效。普通用户无法通过改前端状态、改请求参数或直接访问 API 提权，所有管理接口都在后端重新校验身份、状态和角色。

## 登录防护与限流

以下变量的默认值来自 `.env.example`，按用途分组：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MEW_REGISTER_DEVICE_LIMIT` | `3` | 同一浏览器设备最多成功注册账号数；`0` 表示关闭 |
| `MEW_REGISTER_IP_LIMIT`<br>`MEW_REGISTER_WINDOW_SECONDS` | `10`<br>`86400` | 同一 IP 在统计窗口内的注册尝试上限 |
| `MEW_LOGIN_IP_LIMIT`<br>`MEW_LOGIN_WINDOW_SECONDS` | `20`<br>`600` | 同一 IP 在统计窗口内的登录尝试上限 |
| `MEW_LOGIN_FAILURE_LIMIT`<br>`MEW_LOGIN_LOCK_SECONDS` | `5`<br>`300` | 同一账号连续输错密码后锁定的次数与时长 |
| `MEW_AUTH_HASH_CONCURRENCY` | `2` | 同时运行的 Argon2 哈希/校验任务数 |

登录成功或修改密码成功后，失败计数会被清除。`MEW_AUTH_HASH_CONCURRENCY` 是防止攻击打满 CPU 的信号量，小型服务器建议保持默认的 `2`。

## 会话与 Cookie

- 会话 Cookie 使用 `SameSite=Lax`，Session 存在 SQLite 而不是仅内存；过期会话由后台任务周期清理。
- HTTPS 部署把 `MEW_SESSION_SECURE` 设为 `true`。
- 跨域访问使用显式白名单 `MEW_ALLOWED_ORIGINS`，不会镜像任意 Origin；带 Cookie 的认证接口只接受白名单内来源。
- 登录成功时会轮换 Session ID；密码变更、账号禁用、账号删除以及角色与审批状态变化都会让旧会话失效。

> 🛑 **信任代理头有前提**
>
> 只有在后端无法被公网绕过、请求都经过 Nginx/NPM 时，才把 `MEW_TRUST_PROXY_HEADERS` 设为 `true`，并同时用 `MEW_TRUSTED_PROXY_CIDRS` 限定实际反向代理的 IP/CIDR。不匹配的连接仍然使用直连 IP；否则限流会被伪造的 `X-Forwarded-For` 绕过。

## 重置密码的影响

管理员二次确认后可以给任意账号（含普通账号与其他管理员）重置一次性临时密码。重置会清除锁定状态、递增 Session 版本，使该账号的旧会话立即失效，并要求下次登录时修改密码。
